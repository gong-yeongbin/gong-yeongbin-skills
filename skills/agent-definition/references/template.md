# 에이전트 정의 파일 규격

`agent-definition` 가 만드는 에이전트 정의 파일의 단일 규격이다. author 는 이 규격대로 쓰고, reviewer 는 이 규격으로만 판정한다.

## 파일

- 경로는 `.claude/agents/<name>.md` 이며 파일명은 프론트매터의 `name` 과 같다.
- 구성은 프론트매터 5개 필드와 본문 7개 섹션이다. 순서를 바꾸지 않는다.
- 본문은 한국어로 쓴다.

## 프론트매터 5개 필드

| 순서 | 필드 | 필수 | 규칙 |
|---|---|---|---|
| 1 | `name` | 필수 | 소문자 kebab-case. `:` 를 쓰지 않는다. 프로젝트의 기존 에이전트와 겹치지 않는다. |
| 2 | `description` | 필수 | 큰따옴표로 감싼 한 줄. "무엇을 하는가" 와 "언제 호출하는가" 를 모두 담는다. 호출 여부가 이 문장으로 결정된다. |
| 3 | `model` | 필수 | `sonnet`, `opus`, `haiku`, `fable`, `inherit` 중 하나. |
| 4 | `tools` | 필수 | 쉼표로 구분한 도구 이름. 역할에 필요한 최소 집합만 적는다. `Skill` 은 적지 않는다. |
| 5 | 선택 필드 | 선택 | 아래 표에 있는 필드만, 명세에 근거가 있을 때만 넣는다. 없으면 생략한다. |

Claude Code 는 `name`, `description` 만 필수로 보지만, 이 규격은 `model` 과 `tools` 도 반드시 적게 한다. 생략하면 메인 세션의 모델과 모든 도구를 물려받아 에이전트의 범위가 파일에 드러나지 않기 때문이다.

### 선택 필드

필드명은 대소문자를 구분한다. 표에 없는 이름은 Claude Code 가 경고 없이 무시하므로 쓰지 않는다.

| 필드 | 값 | 넣는 경우 |
|---|---|---|
| `disallowedTools` | `tools` 와 같은 형식 | 특정 도구를 명시적으로 막아야 할 때 |
| `permissionMode` | `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan` | 권한 확인 방식을 바꿔야 할 때 |
| `maxTurns` | 양의 정수 | 턴 수 상한이 필요할 때 |
| `skills` | 스킬 이름 목록 | 시작할 때 특정 스킬 본문을 미리 읽혀야 할 때 |
| `memory` | `user`, `project`, `local` | 세션을 넘어 기억을 유지해야 할 때 |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max` | 추론 강도를 고정해야 할 때 |
| `isolation` | `worktree` | 별도 git worktree 에서 작업해야 할 때 |
| `background` | `true` | 항상 백그라운드로 돌려야 할 때 |
| `color` | `red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan` | 표시 색을 구분하고 싶을 때 |

## 본문 7개 섹션

본문은 `# <에이전트 제목>` 한 줄로 시작하고, 아래 7개 섹션을 `##` 제목 그대로 이 순서로 둔다. 섹션을 빼거나 더하지 않는다.

| 순서 | 섹션 | 담는 내용 | 형식 |
|---|---|---|---|
| 1 | 핵심 역할 | 이 에이전트가 수행하는 단계. | 번호 목록 2~5개 |
| 2 | 작업 원칙 | 판단 기준, 제약, 금지 사항. | 불릿 목록 |
| 3 | 입출력 프로토콜 | 무엇을 읽고 무엇을 어디에 어떤 형식으로 내는가. | `입력.` `출력.` `형식.` 세 불릿 |
| 4 | 팀 통신 프로토콜 | 누구에게서 무엇을 받고, 누구에게 무엇을 넘기는가. 주고받는 파일 경로나 메시지 형식. | `수신.` `발신.` 두 불릿 |
| 5 | 에러 핸들링 | 입력 누락, 도구 실패, 판단 불가일 때의 행동. | `상황 → 행동` 불릿 목록 |
| 6 | 협업 | 다른 에이전트와의 역할 경계. 이 에이전트가 하지 않고 넘기는 일. | 불릿 목록 |
| 7 | 품질 자체 검증 | 출력을 내기 전에 스스로 확인하는 항목. | `- [ ]` 체크리스트 |

### 섹션 작성 규칙

- 명세(`_workspace/agent-spec.md`)에 없는 내용을 지어내 넣지 않는다.
- 팀 없이 단독으로 쓰는 에이전트는 `팀 통신 프로토콜` 과 `협업` 섹션을 지우지 않고 `- 해당 없음. 단독으로 동작한다.` 한 줄을 적는다.
- 그 밖의 섹션은 `해당 없음` 으로 둘 수 없다.
- `입출력 프로토콜` 의 출력과 `팀 통신 프로토콜` 의 발신이 같은 파일을 가리키면 경로 표기가 일치해야 한다.
- `품질 자체 검증` 의 항목은 예·아니오로 답할 수 있는 문장으로 쓴다.

## 골격

```markdown
---
name: <kebab-case>
description: "<무엇을 하는가. 언제 호출하는가.>"
model: <sonnet|opus|haiku|fable|inherit>
tools: <도구, 도구, 도구>
---

# <에이전트 제목>

## 핵심 역할
1. ...
2. ...

## 작업 원칙
- ...

## 입출력 프로토콜
- 입력. ...
- 출력. ...
- 형식. ...

## 팀 통신 프로토콜
- 수신. ...
- 발신. ...

## 에러 핸들링
- <상황> → <행동>

## 협업
- ...

## 품질 자체 검증
- [ ] ...
```
