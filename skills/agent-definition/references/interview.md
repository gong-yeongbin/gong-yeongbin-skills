# 인터뷰 절차

`_workspace/agent-spec.md` 를 만드는 인터뷰 규칙이다. 메인 세션이 직접 수행한다. 서브에이전트는 사용자에게 질문할 수 없다.

## 원칙

- **한 번에 질문 하나.** 답을 받은 뒤 다음 질문으로 간다. 정말 짝인 두 질문만 한 번에 둘까지 묻는다.
- **상류 질문 먼저.** 그 답이 다른 질문을 가장 많이 풀거나 없애는 질문을 고른다. 답으로 이미 정해진 질문은 묻지 않는다.
- **팩트는 직접 찾는다.** 기존 `.claude/agents/` 의 이름, 팀원 에이전트가 주고받는 파일 경로, 프로젝트 구조처럼 파일로 알 수 있는 것은 묻지 않고 읽는다.
- **결정은 사용자의 것이다.** 추천은 하되 대신 정하지 않는다.

## 질문 형식

```
❓ **Q<n>** - **<질문 제목>**: <질문 본문. 선택지가 있으면 숫자 리스트.>

➡️ <추천 답. 선택지가 있으면 "N (추천)" 과 이유 한 줄.>

(남은 질문 약 <k>개)
```

- 선택지는 `1. / 2. / 3.` 숫자 라벨만 쓴다. 추천 항목 끝에 `(추천)` 을 붙인다.
- 숫자만 답해도 그 선택지로 해석한다.
- "계속", "ok" 같은 답은 결정으로 보지 않는다. 열린 질문을 다시 보여 준다.

## 종료

- 아래 명세 형식의 모든 항목이 정해지면 끝이다.
- 결정 표를 보여 주고 사용자가 확인한 뒤에만 `_workspace/agent-spec.md` 를 쓴다. 확인 전에는 파일을 만들지 않는다.

## 명세 형식

`_workspace/agent-spec.md` 는 아래 항목을 이 순서로 담는다. 항목명은 `references/template.md` 의 필드·섹션과 1:1로 대응한다.

```markdown
# 에이전트 명세

## 프론트매터
- name. <kebab-case>
- description. <무엇을 하는가 + 언제 호출하는가>
- model. <sonnet|opus|haiku|fable|inherit>
- tools. <도구, 도구>
- 선택 필드. <필드: 값 — 근거> 또는 없음

## 제목
<에이전트 제목>

## 팀 구성
- 소속. 단독 | <팀/스킬 이름>
- 팀원. <에이전트 이름: 역할> 또는 없음

## 핵심 역할
1. <단계>

## 작업 원칙
- <판단 기준·제약·금지>

## 입출력 프로토콜
- 입력. <무엇을 읽는가>
- 출력. <어디에 쓰는가>
- 형식. <출력 형식>

## 팀 통신 프로토콜
- 수신. <누구에게서 무엇을> 또는 해당 없음
- 발신. <누구에게 무엇을> 또는 해당 없음

## 에러 핸들링
- <상황> → <행동>

## 협업
- <넘기는 일과 역할 경계> 또는 해당 없음

## 품질 자체 검증
- <예·아니오로 답할 수 있는 확인 항목>
```

- `팀 통신 프로토콜`·`협업` 의 `해당 없음` 은 `팀 구성` 이 `단독` 일 때만 쓴다.
- 그 밖의 항목은 비워 두지 않는다.
