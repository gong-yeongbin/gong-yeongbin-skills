# 서브에이전트 위임 — Agent 도구

create-issues 의 두 위임 지점(Stage 2 리서치, Stage 3 게시)에서 `Agent` 도구를 쓰는 규칙이다. 위임은 선택이다. 작은 저장소라 영역 하나가 몇 초면 끝나거나 본문이 짧으면 메인이 직접 한다. 판단은 어느 경우든 같다.

## 공통 규칙

- 판단·추천·사용자 대화(인터뷰 질문, 게이트)는 메인 세션이 한다. 서브에이전트에게는 리서치(사실·후보·근거 수집) 또는 실행(게시·조립·검증)만 맡긴다. "어느 쪽이 좋은지" 를 묻지 않는다.
- 지시는 파일로 만든다. `<TMP>/<slug>_brief-<n>-<역할>.md`. 프롬프트에는 그 경로와 필수 값만 넣는다. 서브에이전트는 메인 대화를 공유하지 않으므로 필요한 값은 brief 에 전부 명시한다.
- 최종 메시지는 결과 파일 경로와 결론 한 줄(게시는 URL 과 검증 결과)이다. 본문 markdown 을 돌려보내지 말라고 brief 에 명시한다.
- 모델. `haiku` 금지. 얕은 조사(답이 파일에 그대로 있음)와 게시(본문이 이미 파일로 완성돼 있고 재조회 검증이 있다)는 `sonnet`, 그 외 리서치는 `opus`.
- 서브에이전트는 실행 중 질문을 못 한다. brief 에 "판단이 필요하면 멈추고 결과 파일 `## 질문` 에 적은 뒤 종료" 를 넣고, 메인이 답을 붙여 다시 띄운다.
- 동시 워커는 한 메시지에 여러 `Agent` 호출로 띄운다. 서브에이전트가 서브에이전트를 띄우지 않게 brief 에 명시한다.

## 호출 형태

```
Agent(subagent_type: "Explore" | "general-purpose", model: "sonnet" | "opus",
      description: "<slug>-리서치-<영역>" 또는 "<slug>-게시",
      prompt: "<brief 파일 경로> 를 읽고 그대로 수행. 최종 메시지는 결과 파일 경로와 결론 한 줄만.")
```

- 리서치는 읽기 전용이면 `Explore`, SKILL.md 읽기나 명령 실행이 필요하면 `general-purpose`. 게시는 `general-purpose`.
- 리서치 brief 에는 "결정이나 추천은 하지 말 것, 사실·후보·근거 경로만, 확인하지 못한 것은 표시" 를 넣는다.

## 워커 명령 위생 (brief `## 금지` 에 넣는다)

권한 프롬프트가 뜨면 워커가 멈추고 메인은 그것을 알 수 없다.

- `cd <경로> && <명령>` 금지. 절대경로를 쓴다.
- 여러 확인을 한 명령에 `&&`·`;` 로 묶지 않는다. 한 명령에 한 가지.
- `xargs`·`eval`·`sh -c` 금지.
- 파일 삭제(`rm`)·git 쓰기(`add`·`commit`·push 전부) 금지.

## 금지

- 워커 결과를 검증 없이 spec·이슈에 옮기기. 리서치는 Facts 로 승격할 때 출처를 확인하고, 게시는 재조회로 확인한다.
- 워커에게 결정·추천 요청.
